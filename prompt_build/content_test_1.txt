## Problem

The current workflow can correctly scroll until the property images become visible, but then returns:

```text
No property image gallery detected.
```

or OpenClaw does not know how to click the property image.

The problem is that AI visual detection and browser interaction are currently disconnected.

Fix this by making the process:

```text
AI identifies image
        ↓
OpenClaw locates image on CURRENT screen
        ↓
OpenClaw moves mouse to image
        ↓
OpenClaw clicks image
        ↓
Verify Facebook Photo Viewer opened
```

Do NOT rely only on a coordinate from an earlier screenshot.

---

# 1. AI Must Analyze the CURRENT Screenshot

When the content-capture process scrolls and property images become visible, take a fresh screenshot.

Send that screenshot to the vision model.

Ask AI specifically:

> Identify the first visible property image that belongs to the target Facebook post. Ignore Facebook profile images, icons, ads, comments, recommended posts, and unrelated images.

AI should return a structured result such as:

```json
{
  "property_image_found": true,
  "first_property_image": {
    "x": 510,
    "y": 620,
    "width": 420,
    "height": 420,
    "center_x": 720,
    "center_y": 830
  }
}
```

The coordinates are coordinates on the CURRENT screenshot.

---

# 2. Use Screenshot Coordinates to Click

OpenClaw must use the coordinates from the CURRENT screenshot.

Do not use coordinates from an earlier screenshot after the page has moved.

For example:

```text
Current screenshot:
1440 × 900

AI identifies:
x = 510
y = 620
width = 420
height = 420

Center:
x = 720
y = 830
```

OpenClaw should:

```text
Move mouse → 720,830
        ↓
Pause briefly
        ↓
Click
```

Prefer clicking the **center area of the image**, not its edge.

---

# 3. Important: Account for Browser Chrome

Make sure AI coordinates refer to the actual screenshot coordinate system used by OpenClaw.

If the screenshot contains:

```text
Browser toolbar
Facebook page
```

do not accidentally treat browser-relative coordinates as page-relative coordinates.

Use the exact coordinate system returned by the screenshot tool.

If OpenClaw uses a different coordinate system, convert:

```text
Screenshot coordinates
        ↓
Browser viewport coordinates
        ↓
Mouse coordinates
```

Do not guess this offset.

---

# 4. Verify Before Clicking

Before clicking, OpenClaw should move the cursor to the detected image and optionally take a small verification screenshot.

Check:

```text
Is the cursor currently over the identified property image?
```

If yes:

```text
CLICK
```

If no:

```text
Re-analyze current screenshot
```

---

# 5. Verify the Click Worked

Never assume that clicking means the photo viewer opened.

After clicking:

```text
Click
 ↓
Wait for Facebook
 ↓
Capture current screen
 ↓
AI/browser detection
```

Determine whether the Facebook photo viewer opened.

Successful result:

```text
Photo viewer
+
Large property image
+
Next/previous navigation
```

If viewer opened:

```text
IMAGE_VIEWER_OPEN = true
```

Continue to image downloading.

---

# 6. If Click Failed

If the viewer did not open:

```text
IMAGE_VIEWER_OPEN = false
```

do NOT immediately continue to Next.

Instead:

```text
Take fresh screenshot
        ↓
AI identifies first property image again
        ↓
Get new coordinates
        ↓
Move mouse
        ↓
Click again
```

Maximum retry:

```text
3 attempts
```

After 3 failures:

```text
Image click failed
```

Stop the image-download process safely.

# 7. Do Not Require AI to Identify an Entire "Gallery"

This is important.

The AI does NOT need to identify:

```text
Gallery
Image 1
Image 2
Image 3
Image 4
```

before clicking.

It only needs to identify:

> **The first property image that can be clicked to open Facebook's photo viewer.**

Once the viewer opens:

```text
Facebook Photo Viewer
        ↓
Next
        ↓
Next
        ↓
Next
```

the browser handles the gallery.

Therefore use:

```text
AI → Find FIRST property image
```

not:

```text
AI → Find entire gallery
```

# 12. Even Better: Use DOM + AI Together

If the Facebook image is available as a clickable DOM element, prefer DOM targeting over raw coordinates.

The ideal hierarchy is:

```text
1. DOM clickable image
        ↓
2. Current screenshot + AI bounding box
        ↓
3. Mouse coordinate click
```

For example, if OpenClaw can inspect the current page and find an image element inside the target post:

```text
Target Post
   ↓
Clickable image element
   ↓
Get bounding box
   ↓
Click center
```

This is more reliable than screen coordinates.

AI should then be used as the **visual confirmation layer**, not the only mechanism.

# 14. Unified Complete Process: Stop on Image Grid & Click on That Exact Capture

This is the exact, complete two-phase process:

### Phase 1: Content Extraction & Dynamic Scrolling Loop
1. **Take Initial Screenshot (Capture #1)**:
   - AI reads the screenshot and extracts the property description and listing specs verbatim.
2. **Scroll if More Text Below**:
   - If more post text continues below:
     * Scroll down (e.g. +650px).
     * Take next screenshot (e.g. Capture #2).
     * AI reads and extracts the additional text.
3. **The Stopping Condition (Clear Image Grid Detected)**:
   - **Case A: Image Grid is Only Partially Cut Off at Bottom (<220px exposed)**:
     * If the image grid just barely peeks in at the bottom edge of the modal/screen, it is NOT fully exposed for accurate clicking.
     * The system **scrolls down ONCE MORE (+500px)** and takes the next capture so the property photo grid is clearly centered in view.
   - **Case B: Image Grid is Clearly & Prominently Visible (>=250px exposed)**:
     * **IMMEDIATELY STOP TAKING SCREENSHOTS**.
     * **IMMEDIATELY STOP SCROLLING DOWN**.
     * The capture sequence terminates right at that step (e.g. Capture #2 or #3).
     * **NEVER** scroll into the comments section (*"Most relevant"*, user replies, comment input box).

### Phase 2: Direct Coordinate Calculation & Click (On That Exact Same Capture)
1. **Use the Capture Where Image Grid Is Clearly Visible**:
   - **DO NOT** scroll down further.
   - **DO NOT** take new or extra screenshots.
   - Use the **exact same screenshot from Phase 1 where the image grid was fully exposed**.
2. **AI Detects Top-Left First Photo Cell**:
   - AI identifies the bounding box `(x, y, width, height)` of the **top-left first property image cell** within the image grid on that screenshot.
   - Compute the exact center point:
     ```text
     Center X = x + (width / 2)
     Center Y = y + (height / 2)
     ```
3. **OpenClaw Direct Click**:
   - OpenClaw moves the mouse cursor directly to `(Center X, Center Y)` on that same screen.
   - Pauses briefly (0.5s) and clicks once.
   - Facebook's Photo Viewer opens.
   - Download the high-resolution images by clicking "Next" in the Photo Viewer until complete.

```text
┌────────────────────────────────────────────────────────────────────────┐
│ PHASE 1: Content Capture & Dynamic Scroll Loop                         │
│ Capture #1 (Top)      → AI reads post text                             │
│       ↓ (More text below)                                              │
│ Scroll down +650px                                                     │
│       ↓                                                                │
│ Capture #2 (+650px)   → Image Grid barely peeks in at bottom (<220px)  │
│                         ⚠️ PARTIALLY CUT OFF → Scroll ONCE MORE (+500px)│
│       ↓                                                                │
│ Capture #3 (+1150px)  → IMAGE GRID FULLY & CLEARLY CENTERED!           │
│                         ⛔ STOP SCROLLING                              │
│                         ⛔ STOP TAKING FURTHER CAPTURES                │
├────────────────────────────────────────────────────────────────────────┤
│ PHASE 2: Coordinate Calculation & Click (Directly on Capture #3)       │
│ • Use Capture #3 (no extra scrolling, no extra screenshots)            │
│ • AI locates Top-Left First Photo Cell: { x, y, width, height }        │
│ • Compute Center: (Center X = x + width/2, Center Y = y + height/2)    │
│ • OpenClaw clicks (Center X, Center Y) on that screen                  │

└────────────────────────────────────────────────────────────────────────┘
══════════════════════════════════════════════════════════════════════════
```


# 15. Two-Prompt Image Enhancement & Retouching Pipeline

For photo processing, the system supports a chained **Two-Stage Prompt Session** workflow:

```text
📸 Original Downloaded Property Photo
               │
               ▼
┌────────────────────────────────────────────────────────┐
│ 🔷 PROMPT SESSION 1: Primary Base Enhancement          │
│ • Sharpness, clarity, dynamic range upscale            │
│ • HDR tone mapping & window sky dehazing               │
│ • Authentic color accuracy & room geometry restoration │
└────────────────────────────────────────────────────────┘
               │
               ▼ [Produces Enhanced V1 Asset]
┌────────────────────────────────────────────────────────┐
│ 🟣 PROMPT SESSION 2: Post-Enhancement Modification     │
│ • Runs directly on top of Enhanced V1                  │
│ • Adds user-defined tweaks, fixes, or styling elements │
│ • Presets: Twilight / sunset window glow, staging      │
│   texture polish, blue sky replacement, or custom fix  │
└────────────────────────────────────────────────────────┘
               │
               ▼
✨ Final Master Enhanced Asset (V2)
```

### Key Workflow Features:
1. **Chained Execution**: Prompt 1 runs on the original image $\rightarrow$ outputs `Enhanced V1` $\rightarrow$ Prompt 2 takes `Enhanced V1` as input and applies secondary modifications $\rightarrow$ outputs `Final Enhanced V2`.
2. **Dedicated UI Sessions**: Two independent, editable monospace prompt sessions with preset selectors, character counters, clipboard paste, and on/off toggles.
3. **Batch & Single Photo Support**: Both single photo enhancement in the Studio Lightbox and batch *"Enhance All"* execute this 2-stage pipeline sequentially across all property photos.
