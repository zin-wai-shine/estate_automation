## Problem

The current workflow can correctly scroll until the property images become visible, but then returns:

```text
No property image gallery detected.
```

or OpenClaw does not know how to click the property image.

The problem is that AI visual detection and browser interaction are currently disconnected.

Fix this by making the process:

```text
AI identifies image
        ↓
OpenClaw locates image on CURRENT screen
        ↓
OpenClaw moves mouse to image
        ↓
OpenClaw clicks image
        ↓
Verify Facebook Photo Viewer opened
```

Do NOT rely only on a coordinate from an earlier screenshot.

---

# 1. AI Must Analyze the CURRENT Screenshot

When the content-capture process scrolls and property images become visible, take a fresh screenshot.

Send that screenshot to the vision model.

Ask AI specifically:

> Identify the first visible property image that belongs to the target Facebook post. Ignore Facebook profile images, icons, ads, comments, recommended posts, and unrelated images.

AI should return a structured result such as:

```json
{
  "property_image_found": true,
  "first_property_image": {
    "x": 510,
    "y": 620,
    "width": 420,
    "height": 420,
    "center_x": 720,
    "center_y": 830
  }
}
```

The coordinates are coordinates on the CURRENT screenshot.

---

# 2. Use Screenshot Coordinates to Click

OpenClaw must use the coordinates from the CURRENT screenshot.

Do not use coordinates from an earlier screenshot after the page has moved.

For example:

```text
Current screenshot:
1440 × 900

AI identifies:
x = 510
y = 620
width = 420
height = 420

Center:
x = 720
y = 830
```

OpenClaw should:

```text
Move mouse → 720,830
        ↓
Pause briefly
        ↓
Click
```

Prefer clicking the **center area of the image**, not its edge.

---

# 3. Important: Account for Browser Chrome

Make sure AI coordinates refer to the actual screenshot coordinate system used by OpenClaw.

If the screenshot contains:

```text
Browser toolbar
Facebook page
```

do not accidentally treat browser-relative coordinates as page-relative coordinates.

Use the exact coordinate system returned by the screenshot tool.

If OpenClaw uses a different coordinate system, convert:

```text
Screenshot coordinates
        ↓
Browser viewport coordinates
        ↓
Mouse coordinates
```

Do not guess this offset.

---

# 4. Verify Before Clicking

Before clicking, OpenClaw should move the cursor to the detected image and optionally take a small verification screenshot.

Check:

```text
Is the cursor currently over the identified property image?
```

If yes:

```text
CLICK
```

If no:

```text
Re-analyze current screenshot
```

---

# 5. Verify the Click Worked

Never assume that clicking means the photo viewer opened.

After clicking:

```text
Click
 ↓
Wait for Facebook
 ↓
Capture current screen
 ↓
AI/browser detection
```

Determine whether the Facebook photo viewer opened.

Successful result:

```text
Photo viewer
+
Large property image
+
Next/previous navigation
```

If viewer opened:

```text
IMAGE_VIEWER_OPEN = true
```

Continue to image downloading.

---

# 6. If Click Failed

If the viewer did not open:

```text
IMAGE_VIEWER_OPEN = false
```

do NOT immediately continue to Next.

Instead:

```text
Take fresh screenshot
        ↓
AI identifies first property image again
        ↓
Get new coordinates
        ↓
Move mouse
        ↓
Click again
```

Maximum retry:

```text
3 attempts
```

After 3 failures:

```text
Image click failed
```

Stop the image-download process safely.

---

# 7. Do Not Require AI to Identify an Entire "Gallery"

This is important.

The AI does NOT need to identify:

```text
Gallery
Image 1
Image 2
Image 3
Image 4
```

before clicking.

It only needs to identify:

> **The first property image that can be clicked to open Facebook's photo viewer.**

Once the viewer opens:

```text
Facebook Photo Viewer
        ↓
Next
        ↓
Next
        ↓
Next
```

the browser handles the gallery.

Therefore use:

```text
AI → Find FIRST property image
```

not:

```text
AI → Find entire gallery
```

---

# 8. Better Detection Question

Do not ask AI:

```text
"Are there property images?"
```

Ask:

```text
"Locate the first clickable property photo belonging to the target Facebook post. Return its bounding box in the current screenshot."
```

This makes the task much more actionable.

Expected response:

```json
{
  "found": true,
  "bbox": {
    "x": 480,
    "y": 540,
    "width": 430,
    "height": 430
  },
  "center": {
    "x": 695,
    "y": 755
  }
}
```

---

```text
┌───────────────────────────────┐

│                               │
│ [ IMAGE 3 ] [ IMAGE 4 ]       │
│                               │

```

AI should select:

```text
IMAGE 1
```

because it is the first property photo.

Return:

```json
{
  "found": true,
  "target": "first_property_image",
  "bbox": {
    "x": 300,
    "y": 500,
    "width": 400,
    "height": 400
  }
}
```

OpenClaw clicks the center.

# 10. If the Image Is Partially Visible

If only part of the first property image is visible:

```text
┌──────────────────────────┐
│                          │
│      PROPERTY IMAGE      │
│                          │
│──────────────────────────│
│ partially below screen   │
└──────────────────────────┘
```

Do NOT click immediately if the clickable area is unreliable.

Instead:

```text
AI detects image partially visible
        ↓
Scroll slightly
        ↓
Take new screenshot
        ↓
AI finds image again
        ↓
Image is sufficiently visible
        ↓
Click center
```

This makes the click much more reliable.

# 12. Even Better: Use DOM + AI Together

If the Facebook image is available as a clickable DOM element, prefer DOM targeting over raw coordinates.

The ideal hierarchy is:

```text
1. DOM clickable image
        ↓
2. Current screenshot + AI bounding box
        ↓
3. Mouse coordinate click
```

For example, if OpenClaw can inspect the current page and find an image element inside the target post:

```text
Target Post
   ↓
Clickable image element
   ↓
Get bounding box
   ↓
Click center
```

This is more reliable than screen coordinates.

AI should then be used as the **visual confirmation layer**, not the only mechanism.

---

# 13. Critical Rule

The system should NOT say:

```text
No property image gallery detected
```

just because the AI cannot understand the word "gallery".

The actual question is:

```text
Can we identify the FIRST CLICKABLE PROPERTY IMAGE
on the CURRENT SCREEN?
```

If yes:

```text
found = true
```

Then OpenClaw clicks it.

---

# 14. Stop at Image Grid — Immediately Terminate Screenshot & Scroll Sequence

When scrolling down and taking sequential screenshots (Capture #1, #2, #3...):

### The Stopping Rule:
1. **AI Analyzes Each Step**: After each scroll step, the screenshot is analyzed by the AI vision model.
2. **Immediate Stop on Image Grid**: As soon as the AI detects that the **Image Grid** (property photos collage / photo grid) has arrived:
   - **IMMEDIATELY STOP taking further screenshots**.
   - **IMMEDIATELY STOP scrolling down**.
   - **DO NOT** continue scrolling into Capture #4, #5, #6, #7...
   - The screenshotting and scrolling process **STOPS RIGHT THERE at the image grid**.
3. **Never Capture Comments**: Never scroll past the image grid into the comments section (*"Most relevant"*, user comments, replies, comment box).
4. **Immediate Transition to Photo Click**: The current screenshot containing the image grid is immediately used to find the first property image, click its center, and open Facebook's Photo Viewer.

```text
┌───────────────────────────────────────────────────────────┐
│ Capture #1 (Top)      → Post text description             │
│ Capture #2 (+650px)   → Additional post text              │
│ Capture #3 (+1300px)  → IMAGE GRID ARRIVED!               │
│                         └─► AI detects Property Image Grid│
│                             ⛔ STOP SCREENSHOT PROCESS    │
│                             ⛔ STOP SCROLLING             │
└───────────────────────────────────────────────────────────┘
═════════════════════════════════════════════════════════════
│ ⛔ NEVER CAPTURE:                                         │
│ Capture #4 (+1950px)  → [BLOCKED] Do not scroll here      │
│ Capture #5 (+2600px)  → [BLOCKED] Do not screenshot       │
│ Capture #6 (+3250px)  → [BLOCKED] Comments section        │
═════════════════════════════════════════════════════════════
```

# Final Expected Behavior

```text
Facebook Post
      ↓
Take Screenshot (Capture #1)
      ↓
AI analyzes: Is Image Grid present?
   ├── NO  → Scroll down → Take next screenshot → Repeat
   └── YES → ⛔ STOP TAKING SCREENSHOTS & STOP SCROLLING
               ↓
         Image Grid is on CURRENT screenshot
               ↓
         AI finds FIRST property image in grid
               ↓
         Return bounding box & center (X, Y)
               ↓
         OpenClaw clicks center of first image
               ↓
         Facebook Photo Viewer opens
               ↓
         Download image 1
               ↓
         Click Next → Download image 2
               ↓
         Click Next → Download image 3 ...
               ↓
         First image appears again → STOP
```

**Key Rules Summary:**
1. **Stop at Image Grid**: As soon as the image grid / photo collage is detected in the screenshot, stop scrolling and stop taking new screenshots immediately.
2. **Zero Comments Screenshot**: Never scroll past the image grid into the comment section.
3. **Click First Photo**: Don't ask AI to parse a full gallery from the feed; find the first clickable property photo in the current screenshot, click it, and let Facebook's Photo Viewer handle high-res gallery downloads.
